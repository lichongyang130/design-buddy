# 核心连接器与真实验证（2026-10-30）

## 产品范围

围绕「资料导入 → 创作 → 交付」只推荐六个入口：飞书、Notion、GitHub、Google Drive、腾讯文档、Slack。前三个排在前面。行业行情、法律、CRM、营销等不再出现在默认目录。原目录保留为 `LEGACY_CONNECTOR_CATALOG`，不再用于推荐或首页菜单。

页面分为：已连接（有服务端远端握手记录的 MCP）、推荐六项、高级设置（自定义 MCP、历史配置、服务调用记录）。旧 `store.state.connectors` 与已有自定义 MCP 元数据不静默删除；旧布尔值 `connected=true` 不再当作远端验证证据。本地规则握手只能标记「本地演示」。全新用户的六项默认均未配置。

## 当前真实支持的接入方式与边界

- 六张品牌卡是用途入口，不是六套已完成的官方 OAuth 适配器。
- 需要用户提供自己有权访问的 MCP 服务 URL 和必要的凭据。没有可用端点就保持未配置；不内置猜测的厂商 URL，不制造授权。
- 成功状态仅为 **MCP 端点握手已验证**，带验证时间；不是厂商账号授权、某业务工具可用、或最新网络在线状态的证明。
- 真正的工具调用通过服务端 MCP 网关执行，结果展示原始 JSON 并可下载。并未添加自动扫描整个网盘、仓库或聊天记录的功能，也未声称实现所有厂商的原生文档导入/回传格式。
- 历史本机 MCP 配置若在当前服务端不存在，显示「已配置，未验证」。网关不可用时保留旧配置，不宣布连接成功。
- 重新验证失败会保存失败状态。重新验证成功会清空工具白名单，要求重新核对行为。断开时必须调用服务端删除配置与凭据；网络失败不只删浏览器记录假装断开。
- 首页「＋ → 连接器」与导入来源图标只跳到管理页，已移除直接切换本地布尔值宣称授权成功的路径。

## 权限与确认

1. 默认所有工具均未授权。通过「管理权限」逐项标记为禁用、只读、写入。
2. 只读判断由有权限的使用者核实。工具名称、远端 annotations 不能证明只读；服务商自身的访问范围仍须限制到用户选定的文档、仓库、频道等。
3. 网关执行工具白名单校验，直接绕过 UI 调用同样被拒绝。未经远端验证的连接也不能运行。
4. 写入每次展示工具名与准确 JSON 参数让用户确认，随后申请 60 秒有效、单次使用、绑定服务/工具/参数的服务端确认凭证；取消确认不会发送调用。不能复用确认凭证或更换参数。
5. 浏览器仅保留公开元数据，不保存接入 Token 原文。现有服务端凭据加密与日志机制保留。
6. 该网关仍是项目既有的单实例本地工作台服务，不是已完成多租户隔离的 SaaS 权限系统。同源头校验不等同于生产用户身份认证；公网多人部署前必须补服务端身份、租户和配置归属鉴权。

## 验证

`npm run test:connector-focus` 使用隔离临时数据目录与本地 Mock MCP 服务，验证实际 HTTP 握手、现代/会话协议调用、默认拒绝、读写白名单、取消/单次/参数绑定确认、配置表单、Token 不落浏览器、服务端断开、失败状态、历史数据保持和移动端。

`node tests/verify-mcp-gateway.mjs` 覆盖原底层 MCP 协议 30 项检查。`npm run test:ui-language` 覆盖四语言和八页回归。Mock 测试通过不等于完成真实厂商授权测试。

旧的 `verify-connectors`、`verify-connector-connect`、`verify-connector-test`、`verify-mcp-ui` 命令入口已统一指向新的真实协议验收，避免继续要求「本地握手即可认定厂商连接成功」或固定 40 卡片的过时契约。原协议单元测试仍独立保留。接入 URL 不接受嵌入式账号密码、查询参数或片段，凭据应使用专门认证字段。

端点握手证据有效期为 30 分钟。过期或缺少可信时间的旧记录归为「已配置，未验证」，留在高级配置中，必须重新验证才能运行；这也避免几天前的测试服务被当成当前在线连接。不会后台轮询业务服务。30 分钟不是持续在线保证。
